## Spacing Scale

**Inherited from Phase 1 verbatim** (multiples of 4). Phase 2 introduces no new spacing tokens. CD-05 specifies the hero's vertical rhythm using these tokens:

| Token | Value | Tailwind class | Phase 2 usage |
|-------|-------|----------------|---------------|
| `xs` | 4px | `gap-1` / `p-1` | Currently accent-dot to statement gap |
| `sm` | 8px | `gap-2` / `p-2` | Nav link inner padding (inherited); channel-button icon-to-handle gap |
| `md` | 16px | `gap-4` / `p-4` | **Hero name → positioning gap** (CD-05); channel-button inner padding (horizontal); footer social icon row gap |
| `lg` | 24px | `gap-6` / `p-6` | **Hero positioning → Currently gap** (CD-05); **Hero channels → CTAs gap** (CD-05); container horizontal padding (mobile) |
| `xl` | 32px | `gap-8` / `p-8` | **Hero Currently → channels gap** (CD-05); Footer band padding (inherited) |
| `2xl` | 48px | `gap-12` / `p-12` | Hero section vertical padding (top + bottom of the hero block); container horizontal padding (desktop) |
| `3xl` | 64px | `gap-16` / `p-16` | Hero text-column ↔ photo-column horizontal gap on desktop (CD-04) |

Channel-button vertical padding uses **12px** (`py-3`) — on-grid (multiple of 4) and not in the named token set above; ships as a literal Tailwind utility since it's a single use site. See ChannelButton contract for the full sizing breakdown.

**CD-05 vertical rhythm** (exact pixel values for the hero stack — planner ships these and tests assert them):

| From → To | Gap (px) | Token | Rationale |
|-----------|----------|-------|-----------|
| Name (`<h1>`) → Positioning | 16px | `md` (`mt-4`) | Tight pair — positioning is the subhead |
| Positioning → Currently | 24px | `lg` (`mt-6`) | Currently is a separate idea, not a subhead |
| Currently → Channels | 32px | `xl` (`mt-8`) | Channels are an action group, deserve a beat |
| Channels → CTAs | 24px | `lg` (`mt-6`) | CTAs are related-but-lower-density per D-20 |

**Photo tile internals (D-02):**
- Photo outer hairline border: `1px` solid `var(--color-border)`.
- Inner padding between border and photo: **8px** (`p-2`). Editorial "tile" framing.
- Photo corner radius: **4px** (`rounded`). Editorial restraint — not pill, not square.

**Exceptions** (Phase-2-specific):
- `view-transition-name: hero-photo` is a CSS property, not a layout spacer.
- Currently accent dot: 6px diameter (between `xs` 4 and `sm` 8) — visual signal, sub-grid by design (CD-02).
- Photo `next/image` explicit width/height: **320×320** on desktop, **240×240** on mobile (D-03 + CD-04). These are content dimensions, not spacers.

All spacers in this phase are multiples of 4. No `0.5`/`2.5` fractional Tailwind utilities are used in any component contract.

- The **hero photo** is the designated LCP element (HOME-04).

## Charcoal Gradient + Grain Overlay

**Inherited from Phase 1 unchanged.** Phase 2 adds no new global background surfaces. The hero, channel buttons, CTAs, and footer all sit on the existing `body` gradient + `body::after` grain layer.

The photo tile (D-02) is **transparent inside the hairline border** — the body gradient shows through the 8px inner padding around the `next/image` element. This is intentional: it keeps the photo feeling "placed on the page" rather than "in a card," matching the editorial restraint. The grain layer is `position: fixed; z-index: -1;` so it does NOT pass through the photo tile — the photo sits above grain — but DOES pass through the 8px transparent padding ring.

**Implementation contract:**

| Property | Value | Source |
|----------|-------|--------|
| Image source | `import portrait from '@/public/portrait.jpg'` — static import enables blur placeholder + LCP preload | D-04 |
| Photo file location | `public/portrait.jpg` — copied verbatim from `~/Projects/braehods/images/photo.jpg` (193KB v1 placeholder) | D-04 |

| Mobile width | 240px — applied via `className="w-60 h-60 md:w-80 md:h-80"` or wrapper rule | CD-04 |
| Aspect ratio | 1:1 (square) — file dimensions and explicit `width`/`height` props must agree | D-03 |
| Border tile | Wrapper `<div className="rounded border border-[var(--color-border)] p-2">` around the `<Image>` | D-02 |
| Inner corner radius on `<Image>` | `rounded-[2px]` (slightly smaller than wrapper's `4px` to reveal the 8px padding ring) | D-02 |
| Object-fit | `object-cover` (in case the portrait file isn't perfectly square) | D-03 |
| View-transition | Inline style on the wrapper `<div>`: `style={{ viewTransitionName: 'hero-photo' }}` | D-21 |
| Animation | **None** — no `fade-in-up`, no opacity transition, no transform | D-24, HOME-04 |
| `aria-hidden` | Not set — the image carries the alt text and is meaningful to the page | A11Y-04 (Phase 6) |

**Why view-transition-name lives in inline style, not a Tailwind class:**
- Tailwind v4 supports arbitrary properties but Phase 2 is the first consumer of `view-transition-name` in this codebase. Inline style is the lowest-friction surface and works in Server Components.
- Alternative: add `@utility view-transition-hero-photo { view-transition-name: hero-photo; }` to `app/globals.css`. Planner's call. Either is acceptable; do NOT use a Client Component to manage it (FOUND-07 invariant).

**Phase 3 contract dependency:** Phase 3's `/about` page must apply the *same* `view-transition-name: hero-photo` value to its photo wrapper for the shared-element transition to fire. Phase 2 does NOT need to verify this — the seam is graceful no-op until Phase 3 wires the matching name (D-21).

**Browser-support contract:** View Transitions API has full Chrome/Edge support, partial Safari (iOS 18.2+), no Firefox. Fallback is "no transition" — both pages still render correctly, just without the cross-fade. This is acceptable; do not polyfill (D-21).

**File:** `components/home/CurrentlyLine.tsx` (Server Component)

**API:**
```tsx

**Visual contract:**

```
● Currently shipping CapitolLens · May 9
└┬┘ └─────────────┬─────────────┘ └──┬─┘

**Implementation:**

| Slot | Element / Class | Notes |
|------|-----------------|-------|
| Wrapper | `<p className="mt-6 flex items-center gap-2 text-base">` | `gap-2` = 8px between dot/statement/date trio |
| Accent dot | `<span aria-hidden className="inline-block w-1.5 h-1.5 rounded-full bg-[var(--color-accent)]" />` | 6px (`w-1.5` = 6px in Tailwind v4). `aria-hidden` — purely decorative. |
| Statement | `<span className="text-[var(--color-text)]">{data.statement}</span>` OR `<a href={data.link}>{data.statement}</a>` if `link` is set | Underline-offset 4 on link variant: `underline underline-offset-4 decoration-1`. |
| Separator | `<span aria-hidden className="text-[var(--color-muted)]">·</span>` | Middle dot in muted color. |
| Date | `<time dateTime={data.updatedAt} className="font-mono text-sm text-[var(--color-muted)]">{formatDate(data.updatedAt)}</time>` | `formatDate` helper formats `2026-05-09` → `May 9` (no year — keeps the line tight; year shown in tooltip via `<time>` semantic). |

**Date formatter contract** (`lib/format.ts` or inline helper):
- Input: ISO `YYYY-MM-DD` string.
- Output: `MMM D` (e.g., `May 9`, not `May 09`).
- Use `Intl.DateTimeFormat('en-US', { month: 'short', day: 'numeric' })`.
- Server-rendered — no client-side date math, no timezone surprises.

**Accessibility:**
- Statement is the meaningful content. Date is supplementary — wrapped in `<time>` so screen readers can read the ISO date if the user navigates to it.
- Accent dot is purely decorative (`aria-hidden`).
- If `link` is set, the statement becomes a real `<a>` with focus ring inherited from `:focus-visible`.

## Motion Choreography (CD-03, full spec)

The motion contract extends Phase 1's `lib/motion.ts` seam. Phase 2 is the first real consumer.

**Stagger sequence on `/` home page load:**

| # | Element | Animation | Delay (`stagger(i)`) | Total time after load |
|---|---------|-----------|----------------------|------------------------|
| — | Hero photo | **None** (LCP element, D-24) | — | renders at first paint |
| — | Name `<h1>` | **None** (typography LCP candidate, D-24) | — | renders at first paint |
| 1 | Positioning subhead | `fade-in-up` 400ms | `stagger(1)` = 80ms | ~480ms |
| 2 | Currently line | `fade-in-up` 400ms | `stagger(2)` = 160ms | ~560ms |
| 3 | Channel button 1 (YouTube) | `fade-in-up` 400ms | `stagger(3)` = 240ms | ~640ms |
| 4 | Channel button 2 (Instagram) | `fade-in-up` 400ms | `stagger(4)` = 320ms | ~720ms |
| 5 | CTA "More about me →" | `fade-in-up` 400ms | `stagger(5)` = 400ms | ~800ms |
| 6 | CTA "See the work →" | `fade-in-up` 400ms | `stagger(6)` = 480ms | ~880ms |

**Note:** CD-03 in CONTEXT.md specifies 240ms duration; Phase 1's `globals.css` ships `fade-in-up` at 400ms duration. **Resolution: ship the 400ms duration from Phase 1.** Re-tuning the keyframe class duration globally would affect any future consumer and breaks the Phase 1 contract. CD-03's per-element delays (80ms increments) are authoritative; the per-element duration matches Phase 1's keyframe (400ms). Total sequence completes ~880ms after page interactive — comfortable, not slow.

**Implementation pattern:**

```tsx
import { fadeInUp, stagger } from '@/lib/motion';

<p className={fadeInUp} style={stagger(1)}>{site.tagline}</p>
<CurrentlyLine ... className={fadeInUp} style={stagger(2)} />
<ChannelButton ... className={fadeInUp} style={stagger(3)} />  {/* YT */}
<ChannelButton ... className={fadeInUp} style={stagger(4)} />  {/* IG */}
<CTAArrowLink ... className={fadeInUp} style={stagger(5)}>More about me</CTAArrowLink>
<CTAArrowLink ... className={fadeInUp} style={stagger(6)}>See the work</CTAArrowLink>
```

**Reduced motion:** Phase 1's global override sets `animation-duration: 0.01ms !important` — animations are effectively instant. Elements still pass through `fade-in-up`'s `from { opacity: 0 }` state but for 0.01ms; final state `to { opacity: 1 }` lands immediately. **Verify on deployed preview** that no flicker is visible in reduced-motion mode (Pitfall 6 — if a flicker appears, the fix is `animation-fill-mode: forwards` already set via the `both` keyword in the `.fade-in-up` rule, which is already in `globals.css`).

**No new motion library, no `motion@12.x` install for Phase 2** — CSS-only via Phase 1's seam (CD-03 in `01-CONTEXT.md`, locked).

**View-transition motion:** Dormant in Phase 2. Phase 3 will tune the cross-fade timing when wiring the matching `/about` photo. Default browser cross-fade is ~250ms — acceptable; revisit in Phase 3.
