### OG Image Fonts (the only Phase-6 font-loading exception)

`ImageResponse` runs in Vercel's Edge Runtime and cannot access `next/font` — fonts must be fetched as raw TTF bytes and passed to the `fonts` array on the `ImageResponse` options. **Phase 6 vendors the Fraunces Bold static TTF to a build-time-only asset path** so the OG generation is byte-deterministic and offline-buildable (per researcher Open Question #3, locked here):

| File | Path | Purpose | Provenance |
|------|------|---------|------------|
| Fraunces 700 TTF | `assets/Fraunces-Bold.ttf` | OG `ImageResponse` font (fetched via `readFile` at build/edge invocation) | Downloaded once from Google Fonts (https://fonts.gstatic.com/.../Fraunces-Bold.ttf, weight 700, static — not variable; ImageResponse does NOT support variable fonts at edge). MD5 documented inline in the OG image source file. |

**Do NOT vendor to `public/`** — that would serve the TTF publicly (180KB+ download for any visitor who guesses the path) with no caller. `assets/` is gitignored from public serving (just a source folder); the OG route segment imports it via `readFile(path.join(process.cwd(), 'assets/Fraunces-Bold.ttf'))` (Node) or `fetch(new URL('../../../assets/Fraunces-Bold.ttf', import.meta.url))` (Edge — preferred per Next 16 docs).

**Fallback if fetch fails:** Geist Sans (inherited body sans) as the second `fonts` entry. The `ImageResponse` library picks the first available font per text element; if Fraunces TTF read fails (vendor file missing, edge runtime hiccup), the title renders in Geist Sans rather than crashing. Document fallback render in the OG image source file's leading comment.

### CTAArrowLink Adaptation (NEW — Phase 6 extends Phase 2 D-19)

The existing `components/home/CTAArrowLink.tsx` (Phase 2 D-19) renders `{children} <span>→</span>` with a forward `→` glyph that hover-translates `+4px` on the X-axis. For the 404 "← Back home" link, the glyph + direction should flip:

```tsx
// Updated component signature (Phase 6 extension):
interface CTAArrowLinkProps {
  href: string;
  children: string;
  staggerIndex: number;
  direction?: 'forward' | 'back'; // NEW — defaults to 'forward'
}
```

Behavior:
- `direction='forward'` (default — backwards-compat with Phase 2 hero CTAs + Phase 5 success-state "Send another →"): renders `{children} <span>→</span>`; hover translates `→` by `+4px` X (`group-hover:translate-x-1`).
- `direction='back'` (NEW — used by the 404 return link only): renders `<span>←</span> {children}`; hover translates `←` by `-4px` X (`group-hover:-translate-x-1`).

The `direction='back'` variant is the **only** Phase 6 component contract change. Plan-phase MUST stage this as an atomic-binding refactor (per Phase 5 D-05 atomic pattern + 06-CONTEXT D-07 inherited) — the prop addition + the 404 page consumer + a renamed prop on existing call sites (NONE — all existing callers omit `direction` and inherit `'forward'` default) MUST land in a single commit. Existing `tests/cta-arrow-link.spec.ts` (if it exists) re-runs against the default `'forward'` behavior unchanged; a new `tests/not-found-renders.spec.ts` asserts the `'back'` glyph + translate direction on the 404 page render.

## Static `/` OG Image (`app/opengraph-image.png`)

**File**: `app/opengraph-image.png` — Next 16 App Router file convention. Next auto-generates the `<meta property="og:image" content="..." />` tag from this file. **Filename is load-bearing** (`opengraph-image.png`); rename breaks the metadata wire.

**Dimensions**: 1200 × 630 px (standard OG). Format: PNG (RGB, no alpha — social-card thumbnails strip alpha on some platforms).

**Build provenance (per researcher Open Question #3, locked here):** **Generate via a one-off Node script at `scripts/build-static-og.mjs`** that uses Next's `next/og` `ImageResponse` API (same engine the dynamic OG images use, but executed at build time and written to disk). This makes the static `/` OG image byte-deterministic and reproducible — re-running the script produces an identical PNG. The alternative (Photoshop/Figma export) introduces a manual visual-tweak step that can drift on re-export and adds a non-versioned design source dependency.

```
scripts/build-static-og.mjs                    # Node script — runs once on demand, output committed
app/opengraph-image.png                        # The committed output PNG
```

The script:
1. Reads the monogram path from `components/ui/MonogramMark.tsx` (or imports `MonogramMark` via a `.mjs`-compatible build) — same path data as `app/icon.svg` per Phase 1 D-04 byte-identical contract.
2. Reads `assets/Fraunces-Bold.ttf` (the vendored TTF — see § OG Image Fonts).
3. Renders the composition via `ImageResponse`.
4. Writes the PNG buffer to `app/opengraph-image.png`.

`scripts/build-static-og.mjs` is **NOT** run on every build (the PNG is committed to the repo as a static asset). The script is documented and re-runnable for monogram/wordmark updates in v1.x. README notes the command (`node scripts/build-static-og.mjs`).

## Dynamic `/about` + `/work` OG Images (`app/<route>/opengraph-image.tsx`)

**Files** (Next 16 App Router file convention):

| Route | OG image source | Generated URL |
|-------|----------------|---------------|
| `/about` | `app/about/opengraph-image.tsx` | `/about/opengraph-image` |
| `/work` | `app/work/opengraph-image.tsx` | `/work/opengraph-image` |

Each file exports:
- A default async function returning `ImageResponse` (the actual image generator)
- `export const alt = "..."` — alt text for the `<meta property="og:image:alt">` tag
- `export const size = { width: 1200, height: 630 }`
- `export const contentType = 'image/png'`

**Composition template (pixel-precise — same for both routes, only the title text varies):**

```
1200 × 630 canvas
┌──────────────────────────────────────────────────────────────┐
│ ┌────┐                                                       │
│ │ B  │  ← 64px monogram at (80, 80)                          │
│ └────┘                                                       │
│                                                              │
│                                                              │
│                                                              │
│                       <Route Title>                          │  ← 128px Fraunces 700
│                                                              │
│                                                              │
│                                                              │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

| Property | Value |
|----------|-------|
| Background gradient | `linear-gradient(135deg, #1a1a1f 0%, #0a0a0a 100%)` (same as static `/` OG — visual family consistency) |
| Grain overlay | same as static `/` OG (inline SVG data-URI, opacity 0.04, no blend mode) |
| Monogram | `MonogramMark` SVG path inlined directly in JSX, 64 × 64 px at position `(80, 80)` (top-left safe margin anchor), `fill="#e8e8e8"`. **Reads the SAME path data as `components/ui/MonogramMark.tsx`** — for the OG ImageResponse JSX, the monogram is inlined as raw `<svg><path d="..." /></svg>` JSX (the path string is shared via a `lib/og/monogram-path.ts` const export so any future monogram update propagates to all 3 surfaces: `MonogramMark.tsx`, `app/icon.svg`, and the OG JSX). |
| Route title | Fraunces 700, 128px font-size, `line-height: 1.05`, color `#e8e8e8`, centered horizontally + vertically (optical center ~y=315), max-width 1040px (canvas minus 80px safe margin × 2), `text-align: center`. Title text sourced from the route's `page.tsx` `metadata.title` field — see § Per-Route Override Hook below. |
| Outer safe margin | 80px |

**Per-Route Override Hook (CONTEXT § Claude's Discretion locked here):**

Each route's `opengraph-image.tsx` defines the title as a top-of-file constant:

```tsx
// app/about/opengraph-image.tsx
const TITLE = 'About';  // future: could read from generateMetadata() output
export const alt = `About Braeden Hodson`;
```

```tsx
// app/work/opengraph-image.tsx
const TITLE = 'Work';
export const alt = `Work — Braeden Hodson`;
```

For v1, the title is **literally "About" and "Work"** (single-word, matches the route's primary `<title>` simple form). v1.x can refactor to read from `page.tsx`'s `generateMetadata()` output (which Phase 6 Plan 06-02 wires per SEO-01) if a per-route title-format drift emerges — but the v1 ship is hard-coded single-word per CONTEXT § Claude's Discretion default.

**`alt` text contract:**
- `/about`: `alt = "About Braeden Hodson"` (descriptive — what the page is, who owns it)
- `/work`: `alt = "Work — Braeden Hodson"`
- Static `/` OG: `alt` not applicable for static PNG (Next reads from `metadata.openGraph.images[].alt` in `app/layout.tsx` — Plan 06-02 sets `alt: "Braeden Hodson — personal site"`)

**ImageResponse runtime:** Edge runtime (`export const runtime = 'edge'`) for fastest first-byte on social-card crawler requests. Edge runtime cannot use `next/font` — fonts loaded via `fetch(new URL('../../assets/Fraunces-Bold.ttf', import.meta.url))` per § OG Image Fonts.

**Fallback render (font fetch failure):** If the Fraunces TTF fetch fails (vendor file missing, edge cold-start hiccup), the title falls through to the second `fonts` array entry — Geist Sans (fetched the same way from `assets/GeistSans-Bold.ttf` — **also vendor at the same time as Fraunces in Plan 06-02 W1 — see Open Question § Geist TTF**). The image still renders with a serif → sans glyph swap that's visually less editorial but functionally correct (the page title still reads on charcoal). Document the fallback in the OG image source file's leading comment.

## Open Questions

**OQ-1 (Geist Sans TTF vendoring):** The OG image template specifies Geist Sans as the fallback font if Fraunces TTF fetch fails (§ Dynamic OG Images Fallback render). The `geist` npm package ships WOFF2 files, not TTF — `ImageResponse` requires TTF/OTF at edge runtime. **Resolution:** Vendor `assets/GeistSans-Bold.ttf` from the Geist GitHub releases page (https://github.com/vercel/geist-font/releases — verify license file ships with the TTF). Same provenance discipline as Fraunces TTF: download once, commit binary, document MD5 in OG image source file leading comment. **Plan-phase action:** Plan 06-02 W1 vendors BOTH `Fraunces-Bold.ttf` AND `GeistSans-Bold.ttf` to `assets/` in a single commit, BEFORE the OG image route segments land. Total committed binary size: ~180KB Fraunces + ~100KB Geist Sans = ~280KB in `assets/` (not served publicly; only loaded at edge build/runtime).

**OQ-2 (404 page heading mobile clamp below 40px floor):** § Typography Hard Rules document the 36px mobile clamp on the 404 heading as a one-time below-floor concession. Plan-phase MUST stage a 320px viewport visual check (single row in `visual-checklist.md`) confirming "Page not found" reads cleanly at 36px Fraunces on actual hardware (not just emulator). If the heading reads poorly (serif strokes thinning on Windows ClearType per Phase 1 Pitfall 3 caution), the documented fallback is `text-3xl` (30px) — even further below floor, accepted because the alternative is heading-wrap which reads worse. **Resolution at audit time:** Plan 06-02 visual-checklist row asserts the 36px render; if it fails on real device, drop to 30px; if 30px also fails, defer the 404 page heading to a different non-Fraunces face (Geist Sans 24px regular as the absolute fallback — documented but expected NOT to trigger).

**OQ-3 (OG static-image regeneration trigger):** The `scripts/build-static-og.mjs` script regenerates `app/opengraph-image.png` on demand. What triggers regeneration? **Locked answer:** Manual — re-run only when the monogram path data OR the wordmark text OR the gradient/grain composition changes. v1 ships the script + the committed PNG; v1.x designer-pass monogram refresh re-runs the script. README documents the command. NOT wired into `next build` (would inflate build time unnecessarily for a static asset that changes ~once per phase). NOT a CI job. Manual invocation is the right call for a single-file static asset on a personal-site cadence.
