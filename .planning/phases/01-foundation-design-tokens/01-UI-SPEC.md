# Phase 1 — UI Design Contract: Foundation + Design Tokens

> Visual and interaction contract for Phase 1. Generated by gsd-ui-researcher from CONTEXT.md (locked decisions), REQUIREMENTS.md (DSGN-* + FOUND-* groups), STACK.md, ARCHITECTURE.md, and PITFALLS.md. Verified by gsd-ui-checker.
>
> **Phase 1 is the establishing phase.** Every later phase inherits these tokens. Renaming or removing one is a project-wide refactor — lock with care.
>
> **shadcn rationale:** shadcn was deliberately NOT initialized for this project (CLAUDE.md explicitly excludes Radix primitives — "the only modal on the site is the contact form. A ~50-line `<dialog>` element ships native"). Tailwind v4 `@theme` is the single design-token surface. No `components.json`, no preset.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4 `@theme` only — see CLAUDE.md "What NOT to Use" / Radix UI primitives row) |

## Spacing Scale

Phase 1 surfaces only `nav`, `footer`, the placeholder hero word, and the hidden `/_tokens` showcase. The scale below is the project-wide contract every phase will inherit (multiples of 4):

| Token | Value | Tailwind class | Usage in Phase 1 | Forward usage |
|-------|-------|----------------|------------------|---------------|
| `xs` | 4px | `gap-1` / `p-1` | — | Icon gaps, inline padding |
| `sm` | 8px | `gap-2` / `p-2` | Nav link inner padding (vertical) | Compact element spacing |
| `md` | 16px | `gap-4` / `p-4` | Nav link inner padding (horizontal), footer gap | Default element spacing |
| `lg` | 24px | `gap-6` / `p-6` | Nav padding-block; `/_tokens` row gap | Section padding |
| `xl` | 32px | `gap-8` / `p-8` | Footer padding-block | Layout gaps |
| `2xl` | 48px | `gap-12` / `p-12` | `/_tokens` section gap; placeholder hero margin | Major section breaks |
| `3xl` | 64px | `gap-16` / `p-16` | Hero block vertical breathing room | Page-level spacing |

**Exceptions:**
- Focus ring offset: `outline-offset: 2px` (the WCAG-recommended off-grid value; not a layout spacer).
- Hairline borders: `1px` (the `--color-border` divider token; sub-grid by design).
- Grain overlay tile: `200px` background-size on the SVG noise — texture pitch, not layout spacing.

## Typography

Type ramp uses **3 sizes + 2 weights** for v1 — restraint is part of the editorial signal. PITFALLS Pitfall 3: **display serif is restricted to ≥40px**; project titles, "Currently" line, body, and captions all use Geist Sans.

| Role | Size (px / rem) | Font | Weight | Line height | Tailwind class | Phase 1 use |
|------|-----------------|------|--------|-------------|----------------|-------------|
| Body | 16px / 1rem | Geist Sans | 400 | 1.5 | `text-base font-sans` | Nav links, footer copyright, `/_tokens` body text |
| UI / Mono | 14px / 0.875rem | Geist Mono | 400 | 1.5 | `text-sm font-mono` | `/_tokens` color hex labels, version/timestamp footer line |
| Display (hero word) | 96px / 6rem (clamp 64→96 mobile→desktop) | Fraunces | 700 | 1.05 | `font-serif text-[6rem] leading-[1.05] font-bold` | Single Fraunces "B" placeholder hero word on `/`; full ramp showcased on `/_tokens` |

**Display ramp on `/_tokens` only** (so later phases can see the full editorial range without committing yet):

| Showcase row | Size | Font | Weight | Line height |
|--------------|------|------|--------|-------------|
| Display XL | 96px | Fraunces | 700 (Black, Soft full) | 1.05 |
| Display L | 64px | Fraunces | 700 | 1.10 |
| Display M | 40px | Fraunces | 600 | 1.15 |

**Hard rules (Pitfall 3):**
- Fraunces is **never** rendered below 40px on any surface.
- Italic Fraunces is **never** used at any size in Phase 1 (italic serif fails on Android Chrome at body sizes — defer until needed and re-test in-browser then).
- All serif text gets `font-feature-settings: 'liga', 'kern'; text-rendering: optimizeLegibility;` (set globally on `.font-serif` utility wrapper or via `@theme` font definition).

**Font-loading contract (Pitfall 4 — FOIT/FOUT):**
- All three fonts loaded via `next/font` in `app/layout.tsx` and exposed as CSS variables on the `<html>` or `<body>` element.
- Fraunces uses `display: 'swap'` (Geist self-hosts; no swap mode needed).
- `adjustFontFallback: true` (default in Next 16 for Google fonts) — automatic metric matching against the system fallback eliminates CLS.
- Verify Lighthouse CLS = 0 on the deployed preview before phase exit.

## Color

Six-token compact palette. Tokens live in `@theme` only inside `app/globals.css` (CONTEXT.md D-07/D-08). All component code uses Tailwind classes; the rare non-Tailwind consumer (`body::after` grain rule, inline SVG `currentColor` callers, future keyframes) reads `var(--color-*)` directly. **No scales — one token per role.**

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| **Dominant (60%)** | `--color-bg-end` | `#0a0a0a` | Primary surface — bottom of charcoal gradient; baseline for all contrast checks |
| **Secondary (30%)** | `--color-bg-start` | `#1a1a1f` | Top of charcoal gradient. Together with `--color-bg-end` produces the CSS gradient `linear-gradient(180deg, var(--color-bg-start), var(--color-bg-end))` on `body` with `background-attachment: fixed` |
| **Body text** | `--color-text` | `#e8e8e8` | Cool-white body copy. ~14:1 against `#0a0a0a`, ~12:1 against `#1a1a1f` — comfortably AA at every gradient point |
| **Muted text** | `--color-muted` | `#a8a8a8` | Timestamps, "Currently" line, captions, footer copyright. **Locked at #a8a8a8 not #707070** (CONTEXT.md D-06 / REQUIREMENTS.md DSGN-03 update). Clears WCAG AA against #0a0a0a (≥7:1) and #1a1a1f (≥6:1) |
| **Accent (10%)** | `--color-accent` | `#7c87ff` | Soft electric blue. **Reserved-for list below.** ~6:1 contrast against `#0a0a0a` |
| **Border** | `--color-border` | `#2a2a2f` | Hairline dividers: nav-bottom, footer-top, `/_tokens` row separators. Decorative only — never load-bearing |

**Accent reserved for** (this list is the project-wide contract; later phases must not extend without revision):
1. **Visible focus ring** on every interactive element via `:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px; }` — globally applied in `globals.css`.
2. **Single hover-lift accent shadow** on interactive cards/links (Phase 2+) — defer Phase 1 since no card surfaces exist yet, but the token is used in the focus ring.
3. **Phase 5 contact form submit button** (background fill).

Accent is **never** used for: body text emphasis, headings, the monogram in nav/footer (uses `--color-text`), generic links (use `--color-text` with underline-on-hover), badge backgrounds (Phase 4 uses border + text + dot pattern, not accent).

**Destructive color:** Phase 1 has zero destructive actions. No destructive token defined for v1. If Phase 5 needs an error state, surface it as plain `--color-text` with an icon + clear copy (PITFALLS Pitfall 9 — color is never the only state indicator). Add destructive token later only if a real destructive action emerges.

**Contrast verification gate (DSGN-09 — phase exit blocker):**
- `--color-text` (#e8e8e8) on `--color-bg-start` (#1a1a1f): must clear ≥4.5:1 ✅ (~12:1)
- `--color-text` (#e8e8e8) on `--color-bg-end` (#0a0a0a): must clear ≥4.5:1 ✅ (~14:1)
- `--color-muted` (#a8a8a8) on `--color-bg-start`: must clear ≥4.5:1 ✅ (~6:1)
- `--color-muted` (#a8a8a8) on `--color-bg-end`: must clear ≥4.5:1 ✅ (~7:1)
- `--color-accent` (#7c87ff) on `--color-bg-end`: must clear ≥3:1 (UI element minimum) ✅ (~6:1)
- **Re-verify with grain layer applied** (PITFALLS Pitfall 2 note: "after applying grain, re-run contrast checks on text sitting under it"). Grain at opacity 0.04 should leave headroom but the audit must run on the deployed preview, not just in design.

## Charcoal Gradient + Grain Overlay (Phase 1 unique surface)

This section captures the visual contract beyond color tokens because the gradient + grain combination is the defining visual artifact Phase 1 ships.

| Property | Value | Source |
|----------|-------|--------|
| Gradient direction | `180deg` (top → bottom) | DSGN-01 |
| Gradient stops | `var(--color-bg-start)` 0% → `var(--color-bg-end)` 100% | DSGN-01 |
| Application | `body { background: linear-gradient(...); background-attachment: fixed; }` | CONTEXT.md D-09 |
| Grain selector | `body::after` (no extra DOM node, no `<GrainOverlay />` component file) | CONTEXT.md D-09 |
| Grain technique | Inline SVG `feTurbulence` data-URI, ≤2KB encoded | DSGN-02, STACK.md grain pattern |
| Grain `baseFrequency` | `0.85` (tune in implementation) | STACK.md grain pattern |
| Grain `numOctaves` | `2` | STACK.md grain pattern |
| Grain `stitchTiles` | `stitch` | STACK.md grain pattern |
| Grain `background-size` | `200px` | STACK.md grain pattern |
| Grain opacity | `0.04` (in 0.03–0.06 band per Pitfall 2) | CONTEXT.md D-09 |
| Grain blend | `mix-blend-mode: overlay` | CONTEXT.md D-09 |
| Grain layer rules | `position: fixed; inset: 0; pointer-events: none; z-index: -1; will-change: auto;` | Pitfall 2 (no layer promotion) |
| Animation | **None.** Grain renders once and stays static. PITFALLS Pitfall 2 explicit: "do not animate the noise" | DSGN-02, Pitfall 2 |

**Known divergence (documented for the implementer):** PITFALLS Pitfall 2 says "Avoid `mix-blend-mode` on a top-level overlay — Chrome and Safari composite blend modes differently and force fullscreen repaints." CONTEXT.md D-09 explicitly chose `mix-blend-mode: overlay` because it produces the dithered film-grain look that prevents banding on the long gradient. **Resolution:** ship D-09 as locked (mix-blend-mode: overlay at opacity 0.04). If `@vercel/speed-insights` real-user data on the deployed preview shows mobile Lighthouse Performance dropping below 95 with `mix-blend-mode` as the identified culprit, drop the blend mode and rely on flat opacity. Phase 1 plan must include this as a tuning checkpoint.

## Motion + Focus Contract

CONTEXT.md `<deferred>` left this to PITFALLS guidance via Claude's discretion (CD-01..CD-03). Phase 1 ships the contract; Phase 1 itself has zero motion to demonstrate it.

### Reduced-motion override (CD-01, A11Y-06, DSGN-08)

Global override in `globals.css`. Components write motion CSS as if motion is always allowed; this rule defaults animation off for users who opt out:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

DSGN-08 reads "all motion gated behind `@media (prefers-reduced-motion: no-preference)`" — that is a higher-level statement of intent that this opt-out pattern implements. The opt-out form is what PITFALLS recommends (Pitfall 6) because it's harder to forget: you don't need to remember to wrap each motion rule.

### Focus ring (CD-02, A11Y-02, DSGN-06)

Global rule, never `outline: none` without an explicit replacement:

```css
:focus { outline: none; }
:focus-visible {
  outline: 2px solid var(--color-accent);
  outline-offset: 2px;
  border-radius: inherit;
}
```

`focus-visible` (not `:focus`) so mouse clicks don't show the ring; keyboard navigation does. Phase 1 verifies this on:
- Every nav link
- Every footer link
- `/_tokens` interactive elements (if any — likely none, but the contract still applies)

**Verification gate:** Tab through the entire deployed preview. Focus indicator must always be visible. axe DevTools must report zero "elements must have visible focus indicator" warnings.

### `lib/motion.ts` isolation seam (CD-03, ARCHITECTURE.md)

Phase 1 ships `lib/motion.ts` even though Phase 1 has no motion of its own. Contents:

```ts
// lib/motion.ts
// Isolation seam for animation. CSS-only for v1; if motion@12.x is ever added,
// this is the one file that changes.

export const respectsReducedMotion = true;

// Class names for staggered fade-in (consumed by Phase 2 hero).
// Keyframes are defined in app/globals.css; this exports the contract.
export const fadeInUp = 'fade-in-up';      // applies @keyframes fade-in-up
export const stagger = (i: number) => ({   // inline-style helper for stagger delay
  '--stagger': `${i * 80}ms`,
} as React.CSSProperties);
```

The `@keyframes fade-in-up` rule lives in `globals.css`. Phase 2 imports `fadeInUp` and `stagger()` and wires them onto the hero — one-import wire-up, no library install.

### Restrained motion menu (DSGN-07)

For reference / Phase 2 onward (Phase 1 does NOT implement these — only the contract is defined):

| Effect | Technique | Phase |
|--------|-----------|-------|
| Staggered fade-in on load | CSS `@keyframes` + `--stagger` inline-style delay | Phase 2 hero |
| Hover lift | `transform: translateY(-2px)` + `transition: transform 200ms cubic-bezier(0.2, 0, 0, 1)` | Phase 2 channel buttons, Phase 4 project cards |
| Section transitions / page reveals | React 19.2 `<ViewTransition>` | Phase 2/3 across-route navigation |

**No motion library for v1.** No `motion@12.x`, no GSAP, no Lenis, no AOS (CLAUDE.md "What NOT to Use" — locked).

## Interaction Contract

| Interaction | Contract |

| Reduced motion | Active globally. Phase 1 has nothing to defeat, but the rule is shipped. |
