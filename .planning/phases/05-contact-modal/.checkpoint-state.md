## Recovered failure categories (carry-forward / defer candidates)

### Category A — Mobile-hamburger spec design (Plan 01 carry-forward, 7 tests on mobile only)

Specs that do `page.goto('/')` then click Nav `Contact` link without opening the mobile hamburger first fail on Pixel 5 because the Contact link is inside a closed `<details>` element and not in the accessibility tree. Fix is in the SPECS, not the source — specs need to detect viewport and open the hamburger summary before clicking. The Plan 01 author wrote the specs assuming desktop-style flat nav.

**Affected specs (mobile-only failures):** contact-modal-opens-from-nav, contact-modal-esc-closes (the `/`-route variant — passes on `/about` route), contact-modal-states (4 tests), contact-modal-honeypot, contact-modal-min-time (2 tests), contact-modal-mailto-fallback (3 tests).

### Category B — `:text-is` vs `innerText` mismatch on mailto arrow (Plan 02 implementation, 4 tests both projects)

The mailto fallback link renders text + `<span aria-hidden>→</span>` (inline-block). DOM `textContent` is `"Or just email me directly →"` BUT `innerText` (which Playwright's `:text-is` uses) renders the arrow on a new line because `inline-block` creates a layout box. Spec asserts `:text-is("Or just email me directly →")` which won't match. Fix is either:

1. Change `inline-block` to a different value that doesn't force a line in `innerText` extraction (`display: inline` but lose hover translate), OR
2. Render arrow as part of the text node (no `<span>`, lose hover translate), OR
3. Use CSS `::after` pseudo-element with `content: "→"; transform: translateX(...)` on hover — preserves both visual + spec match.

**Affected specs:** contact-modal-mailto-fallback (test 1), contact-modal-states (idle state — D-15 mailto verbatim part), contact-modal-mailto-fallback (test 3 — success-state mailto check), contact-modal-states (success state — D-10 success copy is also rendered with split spans causing similar mismatch).

### Category C — Other Plan 02 implementation gaps (3 tests)

- `contact-modal-states.spec.ts:146` error state — error region role/aria-live attributes not matching what the spec expects (`role="alert"` + `aria-live="assertive"`); ContactModal renders the error region but might be missing exact attributes.
- `contact-modal-honeypot.spec.ts:25` + `contact-modal-min-time.spec.ts:26,60` — silent success UI not rendering correctly post-bypass (could be related to `bypassedSuccess` flag flow + the success-state mailto split).

### Category D — `page.url()` vs `window.location.href` after history.replaceState (Plan 01 spec design, 1 test)

`contact-modal-esc-closes.spec.ts:51` reads `page.url()` immediately after ESC to assert hash is cleared. Playwright's `page.url()` may not reflect `history.replaceState` updates synchronously; using `await page.evaluate(() => window.location.href)` would be a more reliable read. Probe confirmed `window.location.href === "http://localhost:3001/"` and `window.location.hash === ""` after ESC, but `page.url()` still reports `#contact`.
